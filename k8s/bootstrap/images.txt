# Images prechargees dans les noeuds kind par `make images-preload`.
#
# POURQUOI CE FICHIER EXISTE
# Les noeuds attaches a la fabric n'ont plus d'egress internet : containerlab
# remplace leur route par defaut (`default via 10.1.1.1 dev eth1`) et la fabric
# n'a aucun NAT vers l'exterieur. kubelet ne peut donc pull AUCUNE image sur
# worker/worker2 — toute image utilisee par le cluster doit figurer ici.
#
# POURQUOI LES DIGESTS SONT ICI ET PAS DANS LES MANIFESTES
# Une image epinglee par digest ne peut pas etre prechargee : `docker save` d'une
# reference a digest produit une archive sans nom (`"RepoTags": null`), que
# containerd enregistre sous un nom invente (`import-<date>@sha256:...`). Kubelet
# ne l'y retrouve jamais et repart en pull reseau.
# La cible `images-preload` pull donc PAR DIGEST (contenu verifie a l'octet pres),
# puis retague en `nom:tag` avant de sauvegarder. L'epinglage ne disparait pas :
# il se deplace du manifeste vers ce fichier, qui devient la source de verite.
# Corollaire : le chart Cilium doit emettre des references SANS digest
# (`useDigest: false` dans cilium-values.yaml), sinon kubelet reclame un nom absent.
#
# FORMAT : une reference complete par ligne, avec son digest. Le tag local est
# derive automatiquement en coupant a partir du `@`.
# Lignes vides et lignes commencant par # ignorees.
#
# POUR METTRE A JOUR apres un bump de CILIUM_VERSION :
#   helm template cilium cilium/cilium --version <X.Y.Z> \
#     --namespace kube-system --values k8s/bootstrap/cilium-values.yaml \
#     | grep -oP '(?<=image: ")[^"]+' | sort -u
#   (le chart, lui, connait les digests : relever ceux qu'il affiche)
